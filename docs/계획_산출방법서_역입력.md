# [고급 기능 계획] 산출방법서를 읽어 조건으로 되돌리기

> 상태: **계획만 수립** (2026-09-20). 구현 전 승인 필요.
> 목표: 회사의 산출방법서 파일(HWP·PDF·DOCX·XLSX)을 올리면 `/builder`의 입력 — 계약조건·기초율·위험률 시트·담보·사업비 — 으로 자동으로 채워 넣는다.

---

## 1. 왜 어려운가 (먼저 알아야 할 제약)

이 기능의 난도는 "문서를 읽는 것"이 아니라 **문서가 제각각이라는 것**에 있다.

| 벽 | 실제로 부딪히는 모습 | 영향 |
|---|---|---|
| **DRM** | 이번에 참조한 `저해지상품/*.hwp`·`*.xlsx`가 전부 `DOCUMENT SAFER V2010 R2`로 암호화되어 열리지 않았다 | 사내 파일 상당수가 **파싱 불가**. 사용자가 DRM 해제본을 올려야 한다 |
| **스캔 PDF** | `용감한 종신 산방서.pdf`는 텍스트 레이어가 없는 이미지였다 | OCR 없이는 글자조차 못 읽는다 |
| **수식 이미지** | 산출방법서의 핵심 수식은 HWP 수식편집기·MathType 객체다. 텍스트로 안 나온다 | 수식 자동 인식은 **범위에서 제외**하고, 구조화된 값만 뽑는다 |
| **표기 비표준** | 같은 것을 α/α_S/계약체결비용/신계약비로 부른다. 1.0/1,000 · 0.1% · 1‰ 이 섞인다 | 사전(synonym) + 단위 정규화가 필수 |
| **위험률표 위치** | 본문이 아니라 별첨 엑셀·부록 표에 있다. 성별·담보별로 시트가 갈린다 | 표 추출은 **별도 경로**로 다룬다 |

→ **결론: 완전 자동은 목표가 아니다.** "초안을 채워 주고 사람이 확인·수정하는" 반자동이 현실적인 목표다. 실패해도 지금처럼 손으로 넣을 수 있어야 한다.

---

## 2. 목표와 비목표

**목표**
- 문서에서 뽑을 수 있는 것을 뽑아 `/builder` 입력 초안을 만든다.
- 뽑은 값마다 **출처(페이지·문단·셀)와 확신도**를 남겨 사람이 검증할 수 있게 한다.
- 못 뽑은 항목은 비워 두고 무엇이 비었는지 알려 준다.

**비목표 (이번 범위 밖)**
- 수식 이미지 → 산식 복원
- DRM 해제
- 산출방법서의 서술을 그대로 재현하는 코드 생성

**성공 기준**: 텍스트가 살아 있는 산출방법서 1건을 올렸을 때, **계약조건·이율·사업비 6항목·해지율**이 사람 손질 없이 맞고, 위험률표는 별첨 파일로 올려 열 이름만 매핑하면 끝나는 상태.

## 3. 구조

```
파일 업로드
  ↓  ① 텍스트화 (브라우저 / 선택적 서버)
텍스트 + 표 + 페이지 좌표
  ↓  ② 항목 추출 (규칙 사전 → 미검출분만 LLM)
Extraction { field, value, unit, source, confidence }[]
  ↓  ③ 정규화·검증 (단위·범위·상호모순)
  ↓  ④ 검수 화면 (좌: 문서 원문, 우: 채워진 단계 카드)
  ↓  ⑤ 확정 → PlanState 로 dispatch
```

### ① 텍스트화 계층 (`lib/import/extract-text.ts`)

| 형식 | 방법 | 비고 |
|---|---|---|
| XLSX·CSV | 이미 있는 `xlsx` (SheetJS) | 위험률 별첨의 주 경로 |
| DOCX | `xlsx`로는 안 되므로 `mammoth` 또는 JSZip + `word/document.xml` 직접 파싱 | 표까지 뽑아야 하므로 XML 직접이 안전 |
| PDF (텍스트) | `pdfjs-dist` — 페이지별 텍스트 + 좌표 | 좌표가 있어야 표를 복원한다 |
| PDF (스캔) | **서버 필요**. Tesseract(한국어) 또는 외부 OCR | v1에서는 "텍스트 없음" 안내만 |
| HWP/HWPX | HWPX(zip+XML)만 지원. 구형 HWP(OLE)는 미지원 | DRM이면 즉시 중단 안내 |

> 판단: **v1은 XLSX·DOCX·HWPX·텍스트 PDF만.** 나머지는 명확한 안내로 끊는다. 스캔 PDF·구형 HWP는 "PDF로 다시 저장해 올려 주세요" 수준의 안내.

### ② 항목 추출 (`lib/import/extract-fields.ts`)

**2단계 전략 — 규칙이 먼저, LLM은 보조.**

**(a) 규칙 사전**: 항목마다 동의어 + 값 패턴을 둔다.

| 필드 | 동의어 | 값 패턴 | 정규화 |
|---|---|---|---|
| `interest` | 적용이율, 예정이율, 이율(i) | `연복리?\s*([\d.]+)\s*%` | % → 소수 |
| `standardInterest` | 표준이율 | 같음 | 같음 |
| `age`/`sex` | 가입연령, 피보험자 | `(\d+)\s*세`, `남|여` | — |
| `termYears` | 보험기간, 만기 | `(\d+)\s*년`, `(\d+)\s*세\s*만기` | 세만기 → 년 |
| `payYears` | 납입기간, 납입 | `(\d+)\s*년납?` | — |
| `freq` | 납입주기, 월납/연납 | 표 | 12/4/2/1 |
| `lapseRate` | 적용해지율, 해지율(w) | `연\s*([\d.]+)\s*%` | 납입 후 0 단서도 같이 |
| `lowRatio` | 저해지·무해지, 환급률, w^r | `([\d.]+)\s*%`, `50%|70%` | 무해지 → 0 |
| `waitMonths` | 면책기간 | `(\d+)\s*일|개월` | 90일 → 3개월 |
| `alphaS` 등 6종 | 계약체결비용/신계약비(α), 계약관리비용/유지비(β), 수금비(γ) | `([\d.]+)\s*/\s*1,?000`, `([\d.]+)\s*%`, `([\d.]+)\s*배` | ‰·% → 소수 |

사업비는 거의 항상 **표**로 온다 → 표 헤더(구분·기호·기준·적용사업비율)를 먼저 찾고 행을 매핑하는 전용 경로를 둔다. 이게 적중률이 가장 높다.

**(b) LLM 보조**: 규칙이 못 찾은 필드만, 그 필드가 있을 법한 문단 ±400자만 잘라 구조화 출력(JSON 스키마)으로 물어본다.
- 전체 문서를 넣지 않는다 — 비용·환각 모두 문단 단위가 유리하다.
- **LLM이 만든 값은 반드시 `confidence: "llm"` 로 표시**하고 검수 화면에서 노란색으로 띄운다.
- 서버 라우트 필요(API 키). 없으면 규칙만으로 동작하고 기능이 꺼진다 — LLM은 **선택 의존성**.

### ③ 정규화·검증 (`lib/import/validate.ts`)
- 단위: %, ‰, /1,000, 배 → 소수. 나이 표기(세만기 ↔ 년만기) 환산.
- 범위: 이율 0~20%, 해지율 0~50%, 사업비율 0~100% 등 — 벗어나면 `warn`.
- 상호 모순: 납입기간 > 보험기간, 무해지인데 환급률 > 0 등.
- **확신도 3단계**: `high`(표에서 직접) / `medium`(본문 정규식) / `low`(LLM 또는 추정).

### ④ 검수 화면 (`/builder/import`)
좌우 2열 — 왼쪽은 문서 원문(추출 위치 하이라이트), 오른쪽은 **지금 쓰는 단계 카드 그대로** 채워진 미리보기.
- 항목마다 `[적용] [무시]` + 출처 뱃지(`p.3 표` / `본문` / `AI 추정`).
- "전부 적용" 버튼 + 미검출 항목 목록.
- 위험률표는 별도 탭: 시트를 보여 주고 **열 ↔ 유형(사망·최초발생·반복지급·기타)·납입면제 매핑**만 사람이 고른다. 이미 있는 붙여넣기·업로드 경로를 그대로 쓴다.

### ⑤ 확정
검수에서 고른 항목만 `planReducer`로 dispatch → 기존 저장·산출 경로를 그대로 탄다. 원본 파일명·추출 로그를 `PlanState.memo`와 산출식 문서(§1)에 남긴다.

## 4. 단계별 일정

| 단계 | 내용 | 산출물 | 크기 |
|---|---|---|---|
| **A** | 텍스트화 계층 + 형식 판별·DRM 감지·안내 | `lib/import/extract-text.ts`, 테스트 | 소 |
| **B** | 위험률 **표** 추출 (XLSX/DOCX 표 → 시트 열) + 열 매핑 UI | 시트에 바로 꽂힘. **단독으로도 쓸모 있음** | 중 |
| **C** | 규칙 사전 기반 스칼라 추출(이율·기간·해지율·면책) + 검증 | `extract-fields.ts` | 중 |
| **D** | 사업비 표 전용 추출 | C와 같은 파일 | 소 |
| **E** | 검수 화면 `/builder/import` | 2열 UI | 중 |
| **F** | LLM 보조 (서버 라우트, 선택) | `app/api/import/route.ts` | 중 |
| **G** | 골든 테스트 — 샘플 산출방법서 3~5건으로 필드별 적중률 측정 | `tests/import/` | 중 |

**권장 순서: B → C → D → E → A(보강) → G → F**
B(위험률 표)가 가장 자주 쓰이고 가장 확실하게 동작하므로 먼저 낸다. F(LLM)는 규칙으로 안 되는 것이 무엇인지 G에서 확인한 뒤에 붙인다.

## 5. 새로 드는 의존성

| 패키지 | 용도 | 크기 | 대안 |
|---|---|---|---|
| `pdfjs-dist` | 텍스트 PDF | 큼(~1MB gz) | 동적 import로 이 화면에서만 로드 |
| `mammoth` 또는 JSZip | DOCX/HWPX | 중 | JSZip + XML 직접(의존성 최소) |
| (서버) OCR·LLM | 스캔 PDF·미검출 필드 | — | 없으면 기능만 꺼짐 |

> 지금 앱은 의존성이 `next·react·recharts·xlsx` 4개뿐이다. **B 단계는 `xlsx`만으로 된다** — 새 의존성 없이 시작할 수 있다는 뜻이고, 그래서 B를 먼저 하자는 것이다.

## 6. 위험과 완화

| 위험 | 완화 |
|---|---|
| 잘못 읽은 값이 조용히 반영 | 검수 화면 없이는 절대 적용하지 않는다. 확신도 뱃지 필수 |
| DRM·스캔으로 대부분 실패 | 업로드 즉시 판별해 "왜 안 되는지"를 명확히 알린다. 실패해도 손 입력 경로는 그대로 |
| LLM 환각 | 문단 한정 + 스키마 강제 + 노란색 표시 + 규칙 결과 우선 |
| 유지보수 부담(회사마다 표기 다름) | 동의어 사전을 **JSON 데이터로 분리**해 코드 수정 없이 늘린다 |

## 7. 먼저 결정해 주셔야 할 것

1. **대상 문서 형식** — B만으로 충분한지(위험률 엑셀만), 본문까지 읽어야 하는지
2. **DRM** — 해제본을 올리는 전제로 가도 되는지
3. **LLM 사용** — 서버 라우트와 API 키를 둘 수 있는지 (없으면 규칙만)
4. **샘플** — 골든 테스트에 쓸 산출방법서 3~5건 (텍스트 살아 있는 것)

1~4가 정해지면 B 단계부터 바로 시작할 수 있습니다.
