## 0. 문서 이력과 결정 요약

### 0.1 v0.1 → v0.2 변경

- 주 사용자를 **설계사(상담 도구)**로 확정하고 고객은 읽기 전용 공유 링크로 분리했다.
- 1차 범위를 신규 설계·비교·제안서로 좁히고 **재설계 모드는 2차**로 옮겼다(규칙 R01~R03, DB 초안은 부록 B에 보존).
- 위험률표·예정이율·사업비·해약공제·저해지 가정을 실제 산출과정표 값으로 **채웠다**(§5.2).
- 프리셋 6종의 배수 벡터와 envelope 미정 기본값을 확정했다(§3.2, §3.3).
- 계산 엔진 명세(§3.4)가 워크북 산식과 1:1로 대응하도록 다시 썼고, 검증 정답값을 명기했다(§7).
- 기술 스택을 Next.js 15 기준으로 갱신하고 Supabase·Playwright·Python 신규 구현을 1차에서 제외했다.

## 1. 목적과 범위

계약자가 연령별 보험금 스케줄을 설계하면 시스템이 규정과 제약(envelope)을 검증하고 평준보험료·준비금·해약환급금·사업비 흐름을 즉시 산출하는 웹 앱을 만든다. **설계사가 상담 자리에서 입력→설계→결과를 한 화면에서 보며 고객에게 제안**하는 것이 1차 목적이며, 같은 엔진이 보험사 제안 시 산출 근거가 된다.

### 1.1 1차(MVP) 포함

- 온보딩 입력(피보험자·가족·재무·기존 보장)과 니즈·HLV 기반 추천
- 프리셋 6종 + 구간 카드 편집, 예산 슬라이더(월 보험료 ↔ 초기 보험금 역산)
- envelope 검증(E01~E09)과 인라인 수정 제안
- 보험료(순·영업), 준비금, 해약환급금, 사업비 흐름, 납입면제·저해지 옵션
- 비교 패널(같은 월 예산: 평준형 종신 / 정기+종신 조합 / 설계형)
- 제안서 인쇄 페이지(PDF), 고객 공유 링크(모바일 읽기 전용)
- 설정 화면(가정 세트·envelope 파라미터 편집)

### 1.2 2차 이후

- 기존 계약 재설계 모드(준비금·미래 보험료를 예산으로, 규칙 R01~R03, 전환 손실 표시) — 부록 B
- Excel 검산 파일 내보내기, 계리 요약 PDF(입력 스냅샷·가정 버전·검증 통과 여부)
- Supabase 저장·고객 목록·로그인, 그래프 위 드래그 편집
- 회사 연계(가정 시트 업로드, 민감도 분석, 계약관리 API 규격)

### 1.3 제외

### 3.2 스케줄 설계

**데이터 모델.** 스케줄은 구간 카드의 배열이다.

```ts
type Block = { fromAge: number; toAge: number; multiple: number; kind: 'death' | 'celebration' }
// death: 해당 연령 구간의 사망보험금 = S0 × multiple
// celebration: fromAge 시점 1회 생존급부(축하금) = S0 × multiple
```

카드를 연 단위로 전개해 `S_t`(사망보장 배수, t = 0 … n−1)와 `C_t`(생존급부 배수, 시점 t)를 만든다. 편집 단위 1년, 화면 눈금 5년. 예산 슬라이더는 **S0만** 비례 조정하고 배수 벡터는 유지한다(납입기간 연금현가가 고정이므로 보험료가 선형으로 움직인다).

**프리셋 6종 (배수 벡터 확정 초안).** x = 가입연령, S0 = 초기 고정 구간 보험금. 모든 변경은 t ≥ 5(E01)부터, 올리든 내리든 매년 최대 한 칸(기준보험금의 10%). 표준 모양은 아래와 같고, 조건을 반영하면 §0.12의 필요액 곡선을 쓴다(2026-09-11 갱신).

| 프리셋 | 배수 정의 | 파라미터(기본) | 대상 |
|---|---|---|---|
| 평준형 | 전 구간 1.0 | — | 기준선·비교용 |
| 자녀연령형 | 막내 독립(25세) 6년 전부터 매년 −0.1, 독립 시점부터 0.3 (v0.9) | 막내 나이, 독립 연령 25 | 30대 맞벌이·영유아 자녀 |
| 부채상환형 | t=5부터 부채 만기까지 1.0 → 0.3 선형 감액(매년 최대 0.1), 이후 0.3 유지 | 부채 만기 연도(표준 20년) | 자영업자·부채 보유 |
| 은퇴증액형 | 은퇴−5년까지 1.0, 5년 램프 1.1→1.5(+0.1/년), 이후 1.5 | 은퇴시기 65(55·60·65·70), 목표 1.5 | 상속·정리자금 |
| 단체보험보완형 | 퇴직−5년까지 0.5, 5년 램프 0.6→1.0(+0.1/년), 이후 1.0 | 퇴직 = 은퇴시기 65 | 단체보험 보유 직장인 |
| 상속준비형 | t<5: 0.5, 이후 매년 +0.1(기준보험금 기준), 2.0 도달(15년) 또는 증액 종료 연령(E03)에서 고정 | 목표 배수 2.0 | 50대 상속 준비 |

경계가 초기 고정 구간(t<5) 안에 오면 변경 시점을 t=5로 미룬다. 증액 램프 시작이 E03을 넘으면 프리셋이 아니라 검증 위반으로 표시한다.

**블록 유형 태그.** 순수보장 / 생존급부(축하금) / 저해지 적용 구간(t<5)을 카드와 그래프에 색으로 표시한다.

### 3.3 제약 검증기(envelope)

순수 함수 `validate(schedule, params, context) → Violation[]`. 위반은 코드·메시지·해당 카드 id·수정 제안을 담는다.

| 코드 | 규칙 | 기본값 | 수정 제안 |
|---|---|---|---|
| E01 | 초기 고정 기간(t < 5) 보험금 변경 불가 | 5년 | 변경 시점을 t=5로 이동 |
| E02 | 연 증가율 상한 | 20% | 램프 연장 |
| E03 | 증액 종료 연령 | 70세 | 램프를 70세 전에 종료 |
| E04 | 최대 배수(S0 대비) | 3.0배 | 배수 축소 |
| E05 | 감액 하한(S0 대비) | 20% | 0.2로 상향 |
| E06 | 최소 보험금 절대액 | 1,000만원 | S0 상향 또는 배수 상향 |
| E07 | 심사 한도: max(S_t·S0) ≤ 언더라이팅·재정심사 한도 | 10억(입력) | S0 축소 |
| E08 | 생존급부 누계 ≤ 그 시점까지 누적 납입 영업보험료 (보장성보험 요건) | 고정 | 축하금 축소·지연 |
| E09 | 저해지 적용 구간 ⊆ 초기 고정 구간 | 구조상 자동 충족 | — |

파라미터는 가정 세트와 별도로 `envelope` 객체에 두고 설정 화면에서 편집한다. 재설계 규칙 R01~R03은 부록 B.

### 3.4 계산 엔진 명세 (v0.1)

워크북 `premium-term`(정기, 7회 표)·`whole-life-multi`(종신 다급부) 산식을 그대로 옮긴다. 두 워크북의 정답값을 **같은 코드**로 재현하는 것이 완료 조건이다(§7).

#### 3.4.1 기호

| 기호 | 뜻 |
|---|---|
| x | 가입연령 |
| ω | 표에서 q=1이 되는 나이: 남 110, 여 112 |
| n | 보험기간 = ω − x. 사망보장 연령 x … x+n−1 (ω세 사망은 원본 관행대로 제외, 기여도 10만원당 0.002원 미만) |
| m | 납입기간 |
| mm | 연 납입 횟수 = 12 (월납) |
| i, v | 예정이율, v = 1/(1+i) |
| q_t, f_t | t년차 사망률, 납입면제 사유(장해 50% 이상) 발생률. 납입면제 OFF면 f_t = 0 |
| S_t, C_t | 사망보장 배수, 생존급부 배수(기준보험금 S0 = 1 단위 기준) |

모든 산출은 **기준보험금 1단위(10만원)당**으로 하고 마지막에 S0를 곱한다.

#### 3.4.2 생존자표와 계산기수

```
lx[0]  = lx′[0] = 100000
lx[t+1]  = lx[t]  · (1 − q_t)                        # 급부 집단: 사망만
lx′[t+1] = lx′[t] · (1 − q_t − f_t + q_t·f_t/2)      # 납입 집단: 사망 + 납입면제
Dx[t]  = lx[t]·v^t          D′x[t] = lx′[t]·v^t
Cx[t]  = lx[t]·q_t·v^(t+0.5)                          # 연중앙 사망
Nx[t]  = Σ_{u≥t} Dx[u]      N′x[t] = Σ_{u≥t} D′x[u]   # 역누적
```

급부는 lx, 납입은 lx′로 센다. 납입이 면제된 계약도 보장은 유지된다.

#### 3.4.3 급부 현가와 순보험료

```
PVB  = Σ_{t<n} S_t·Cx[t] + Σ_t C_t·Dx[t]              # 가변 스케줄이므로 Mx 차분 대신 직접 합
N*   = mm·[ (N′x[0] − N′x[m]) − (mm−1)/(2·mm)·(D′x[0] − D′x[m]) ]   # 월납 보정 납입기수
P    = PVB / N*                                        # 순보험료(1회 납입, 월)
base = PVB / (N′x[0] − N′x[M]),  M = min(n, 20)         # 기준연납순보험료
```

평준 스케줄(S_t ≡ 1)이면 PVB = Mx[0] − Mx[n]으로 종신 공식과 같고, 정기 형태(만기 이후 0)면 정기 공식과 같다(§7 G3·G4).

#### 3.4.4 영업보험료

사업비 기호는 엔진 고유명으로 통일한다. **두 워크북은 α1/α2와 β1/β2의 뜻이 서로 뒤바뀌어 있으므로** 값을 옮길 때 아래 표로 매핑한다.

| 엔진 기호 | 뜻 | `premium-term`(경영인정기) | `whole-life-multi`(종신공제) |
|---|---|---|---|
| α_S | 신계약비 정액(기준보험금 비례) | α2 = 10/1000 | α1 = 10/1000 |
| α_P | 신계약비율(기준연납순보험료 비례) | α1 = 5%×min(n,20) | α2 = 5%×min(n,20) |
| β_S | 유지비 정액(기준보험금 비례, 납입 1회당 /mm) | β2 = 1.5/1000 | β1 = 0.4/1000 |
| β_G | 유지비율(영업보험료 비례) | β1 = 4.5% | β2 = 7% |
| β′ | 납입 후 유지비 정액 | 1/1000 | 0.4/1000 |
| γ | 수금비율(영업보험료 비례) | 2.5% | 4% |

**산출방법서형** (`expenseModel: 'method'`):

```
G = [ P + (α_S + α_P·base)·D′x[0]/N* + β_S/mm + β′·(Nx[m] − Nx[n])/N* ] / (1 − β_G − γ)
```

**3이원 단순형** (`expenseModel: 'simple'`, PremiaFlow 방식 A와 동일 구조):

```
G = [ P + α·D′x[0]/N* + β·(Nx[0] − Nx[n])/N* ] / (1 − γ)      # α: 가입금액 비례 1회, β: 가입금액 비례 연간
```

- 신계약비(1단위당) = α_S + α_P·round(base, 5). 원본은 기준연납을 소수 5자리로 반올림한 뒤 곱한다.
- 부가보험료 분해(신계약비·유지비·수금비·납입후유지비)와 연도별 사업비 흐름을 함께 반환한다.
- 예산 역산: S0 = 월 예산 / G(1단위). 스케줄이 바뀌면 G가 바뀌므로 다시 계산한다.

#### 3.4.5 준비금

연말 책임준비금(순보식 + 납입후유지비), 1단위당:

```
P_β   = ( PVB + β′·(Nx[m] − Nx[n]) ) / (N′x[0] − N′x[m])                 # β′ 포함 연납순보험료
V_t   = [ Σ_{u≥t, u<n} S_u·Cx[u] + Σ_{u>t} C_u·Dx[u]
        + β′·(Nx[max(t,m)] − Nx[n])
        − P_β·(N′x[t] − N′x[m])·[t ≤ m] ] / Dx[t]
```

표준기초(표준이율·표준사망률·표준발생률)로 같은 식을 돌린 값이 표준준비금이다(1차에서는 표시·검증용).

#### 3.4.6 해약환급금

```
신계약비 α  = min( 적용기초 α, 표준기초 α )                   # α = α_S + α_P·round(base,5)
해약공제_t  = α · max(min(m,7) − t, 0) / min(m,7)             # 7년 상각
W_t         = max(V_t − 해약공제_t, 0)
환급률_t    = W_t / ( min(t,m)·mm·G )
```

#### 3.4.7 저해지 (초기 5년 고정 구간) — v0.4 §0.6 #23으로 대체됨

가정 세트 `lowSurrender: { ratio: 0.5, lapse: 0.04 }`. 해지율 4%는 무해지 워크북의 가정을 따른다.

```
W^저_t = ratio·W_t   (1 ≤ t ≤ 5),   W_t (t > 5)
ΔP     = Σ_{t=1..5} lx′[t]·lapse·(1 − ratio)·W_t·v^t / N*      # 해지 시 덜 돌려주는 금액의 현가를 보험료에서 차감
P^저   = P − ΔP,  G^저는 P^저로 3.4.4 재계산
```

`ponytail:` 해지자의 납입 중단을 N*에 반영하지 않은 단순화. 승격 경로는 `nonsurrender` 워크북의 해지율 이중탈퇴 현금흐름과 표준해약공제 한도(`S = min(rounddown(net/term, 2), 1)`) 방식.

#### 3.4.8 비교 지표

초기 보험금(S0), 보험금 현가(PVB·S0), 총납입(G·mm·m), 납입 완료 시점 환급률, 보장 배수(max S_t·S0 / 연소득).

#### 3.4.9 반올림 관행 (원본 일치)

- 내부 계산은 반올림하지 않는다.
- 10만원당 순·영업보험료, 준비금, 신계약비는 원 단위 반올림(half-up, Excel ROUND)하고 그 값에 가입금액 배수를 곱한다.
- 해약환급금은 가입금액 기준으로 원 단위 반올림한다.
- 기준연납순보험료는 신계약비 산출 시에만 소수 5자리 반올림값을 쓴다.

#### 3.4.10 구현 원칙

- `lib/engine/`은 순수 TypeScript 모듈, UI·브라우저 API 의존 없음. `compute(input, assumptions) → Result` 한 진입점.
- 입력은 number input 범위 + clamp로 검증(v0.3). 결과에는 입력 스냅샷·가정 세트 id·버전·envelope 통과 여부를 함께 담는다(감사추적).
- 계산 경로에 LLM·`eval` 사용 금지(PremiaFlow 원칙).

### 3.5 추천 로직 (니즈 + HLV)

가정 세트 `needs: { discount: 0.02, livingRatio: 0.7, selfRatio: 0.3, educationPerChild: 1억, finalExpense: 3천만, independenceAge: 25, retirementAge: 65 }`. 확정연금 현가 `a(k) = (1 − (1+r)^−k)/r`.

1. **니즈 접근법.** 필요보장 = 연소득×livingRatio×a(막내 25세까지 연수) + 자녀 수×educationPerChild + 부채 잔액 + finalExpense − 기존 보장 − 유동자산.
2. **HLV.** 인적자본 = 연소득×(1 − selfRatio)×a(은퇴까지 연수).
3. 두 값을 초기 보험금 후보로 나란히 보여 주고, 가족·부채·기존 보장 정보로 프리셋을 고른다: 자녀 있음 → 자녀연령형, 부채 만기 있음 → 부채상환형, 단체보험 있음 → 단체보험보완형, 50세 이상·자녀 독립 → 상속준비형, 그 외 → 평준형. 구간 경계(막내 25세, 부채 만기, 단체보험 만기, 은퇴)를 자동 설정한다.
4. 결과를 envelope에 투영(E04·E05·E06 클램프, E01 경계 이동)한 뒤 예산 입력 시 S0를 비례 조정한다.

### 3.6 비교 패널

같은 **월 예산** B에서 세 안의 S0를 각각 역산한다.

| 안 | 정의 |
|---|---|
| 평준형 종신 | S_t ≡ 1, m년납 |
| 정기 + 종신 조합 | 종신 S_W = 설계형 최종 구간 배수, 정기 S_T = S0 − S_W(만기 = 설계형의 첫 감액 시점, 납입 = min(m, 만기)). 두 계약을 같은 가정 세트로 각각 산출해 합산 |
| 설계형 | 현재 스케줄 |

지표 표(§3.4.8) + 그래프 겹쳐 보기. 조합안의 정기 사업비는 종신과 같은 세트를 적용한다(§8 리스크).

**사용자 편의 원칙**

1. 입력 변경 즉시 재계산(`useMemo`). 저장 버튼 없음(localStorage 자동 저장).
2. 기본값만으로 결과에 도달한다. 필수 입력은 성별·연령·예산 3개.
3. envelope 위반은 해당 카드에 인라인으로 표시하고 "자동 수정" 버튼을 제공한다.
4. 금액 입력은 만원 단위, 표시는 원 단위 천 단위 구분. 배수 ↔ 금액 토글.
5. 프리셋을 먼저 노출하고 커스텀 카드 편집은 접힌 상태로 둔다.
6. 결과 화면의 모든 숫자는 "근거 보기"로 산식·중간값을 펼칠 수 있다.

## 부록 B. 2차 항목 보존 (v0.1에서 이동)

### B.1 재설계 입력 — v0.7에서 구현(§0.9)

기존 보험금, 잔여 납입기간, 현재 준비금 또는 해약환급금, 원계약 예정이율. 이 상품 계약이면 자동 조회.

### B.2 재설계 규칙 — v0.7에서 구현(§0.9)

| 코드 | 규칙 | 기본값 |
|---|---|---|
| R01 | 동일 기초율로 PV(신 스케줄) ≤ PV(구 스케줄) | 고정 |
| R02 | 재설계 후 5년 이내 연도는 기존 이하로만 변경, 증액은 6년째 이후 | 고정 |
| R03 | 재설계 횟수 제한 | 연 1회 |

재설계 예산 = V_t + PV(미래 보험료) − PV(미래 사업비). 결과 = 새 스케줄의 평준보험료 또는 완납 시 실현 가능 보험금. 비교: 원계약 유지 / 감액 / 감액완납 / 연장정기 / 해지 / 재설계. 기존 종신에서 전환 시 기초율 차이 손실을 금액으로 표시. 납입 지속 재설계는 준비금 이월, 납입 중단은 해약환급금 이월(감액완납 기준), 신계약비 미부과.
